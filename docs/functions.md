## 03. 기능 상세

**판단 순서가 있는 기능만 적음.** 아래 여섯은 상세를 두지 않음.

| 번호 | 기능 | 근거 |
| --- | --- | --- |
| FR-02 | 제목 검색 | FR-01 의 조회 조건 |
| FR-03 | 상태별 조회 | FR-01 의 조회 조건 |
| FR-07 | 모집글 삭제 | FR-06 과 판단 순서가 같음 |
| FR-14 | 후기 목록 조회 | 조회만 하며 판단이 없음 |
| FR-18 | 내 모집글 조회 | FR-17 과 절차가 같음 |
| FR-19 | 내 신청 조회 | FR-17 과 절차가 같음 |

**FR-07 은 FR-06 의 절차 1과 2만 거침.** 상태와 정원은 확인하지 않으며, 마감된 모집글도 삭제 가능함.

**FR-18 과 FR-19 는 FR-17 과 같음.** 토큰에서 회원 식별자를 확인하고 조회함. 대상만 다름.

### FR-01 · 모집글 목록 조회

| 항목 | 내용 |
| --- | --- |
| 사용자 | 손님 |
| 선행 조건 | 없음 |
| 담당 | 1 |

**처리 절차**

```
  1. 쪽 번호와 건수를 받는다
  2. 검색어와 상태가 있으면 조건에 포함한다
  3. 최신순으로 정렬해 조회한다
  4. 각 모집글의 수락 인원을 함께 반환한다
```

**예외 처리**

| 상황 | 처리 |
| --- | --- |
| 결과가 없음 | 빈 목록과 함께 200 |
| 잘못된 쪽 번호 | 빈 목록과 함께 200 |

**! 검토 사항**

절차 4의 수락 인원을 모집글마다 따로 세면 조회 구문이 건수에 비례한다. NFR-04 를 만족하는지 확인이 필요하다.

### FR-04 · 모집글 상세 조회

| 선행 조건 | 없음 |

```

### FR-06 · 모집글 수정

| 항목 | 내용 |
| --- | --- |
| 사용자 | 모집자 |
| 선행 조건 | 로그인, 모집 중인 자기 모집글 |
| 담당 | 2 |

**입력 항목은 등록과 같다.**

**처리 절차**

```
  1. 모집글을 조회한다
  2. 모집자 본인인지 확인한다
  3. 상태가 모집 중인지 확인한다
  4. 새 정원이 현재 수락 인원보다 작지 않은지 확인한다
  5. 값을 바꾼다
```

**절차 3과 4가 BR-11과 BR-12에 대응한다.** 마감된 모집글의 정원을 늘리면 자리가 있는데 신청이 막히고, 정원을 수락 인원보다 줄이면 인원이 정원을 넘는다.

**예외 처리**

| 상황 | 응답 | 코드 |
| --- | --- | --- |
| 검증 실패 | 400 | `INVALID_INPUT` |
| 마감된 모집글 | 400 | `STUDY_CLOSED` |
| 정원이 수락 인원보다 작음 | 400 | `CAPACITY_BELOW_ACCEPTED` |
| 인증 부재 | 401 | `UNAUTHORIZED` |
| 모집자가 아님 | 403 | `FORBIDDEN` |
| 대상 부재 | 404 | `NOT_FOUND` |

### FR-09 · 신청

| 항목 | 내용 |
| --- | --- |
| 사용자 | 회원 |
| 선행 조건 | 로그인, 모집 중인 모집글 |
| 담당 | 3 |

**입력 항목**

| 항목 | 필수 | 제약 |
| --- | --- | --- |
| 신청 메시지 | 아니오 | 300자 이하 |

**처리 절차**

```
  1. 모집글을 조회한다
  2. 모집자 본인인지 확인한다
  3. 상태가 모집 중인지 확인한다
  4. 마감일이 지나지 않았는지 확인한다
  5. 이미 신청했는지 확인한다
  6. 상태를 대기로 두고 저장한다
```

**순서가 중요하다.** 대상 확인을 먼저 하지 않으면 없는 모집글에 대해 다른 판단을 시도하게 된다.

**절차 3과 4를 나눈다.** 상태가 마감인 경우와 마감일이 지난 경우는 사유가 다르므로 화면 안내도 달라야 한다. 둘 다 해당하면 상태를 먼저 판단한다.

**예외 처리**

| 상황 | 응답 | 코드 |
| --- | --- | --- |
| 자기 모집글 | 400 | `SELF_APPLICATION` |
| 마감된 모집글 | 400 | `STUDY_CLOSED` |
| 마감일 경과 | 400 | `DEADLINE_PASSED` |
| 이미 신청함 | 400 | `DUPLICATE_APPLICATION` |
| 인증 부재 | 401 | `UNAUTHORIZED` |
| 대상 부재 | 404 | `NOT_FOUND` |

**팀 판단 · BR-13**

| 선택 | 절차 5의 확인 대상 |
| --- | --- |
| 채택 | 상태와 무관한 모든 신청 |
| 미채택 | 대기와 수락 상태의 신청 |

### FR-10 · 신청 취소

| 항목 | 내용 |
| --- | --- |
| 사용자 | 신청자 |
| 선행 조건 | 대기 상태의 자기 신청 |
| 담당 | 3 |

**처리 절차**

```
  1. 신청을 조회한다
  2. 신청자 본인인지 확인한다
  3. 상태가 대기인지 확인한다
  4. 신청을 삭제한다
```

**대기 상태만 취소할 수 있다.** 수락된 신청을 취소하면 아래가 벌어진다.

```
  4 / 4명 · 마감
      ▼  수락된 사람이 취소
  3 / 4명 · 마감          자리가 있는데 신청이 막힌 상태
```

마감은 되돌리는 전이가 없으므로 이 상태를 정합하게 만들 방법이 없다.

**예외 처리**

| 상황 | 응답 | 코드 |
| --- | --- | --- |
| 이미 처리된 신청 | 400 | `ALREADY_PROCESSED` |
| 인증 부재 | 401 | `UNAUTHORIZED` |
| 신청자가 아님 | 403 | `FORBIDDEN` |
| 대상 부재 | 404 | `NOT_FOUND` |

**팀 판단 · BR-15**

| 선택 | 절차 4 |
| --- | --- |
| 채택 | 신청 행을 삭제 |
| 미채택 | 상태를 `CANCELED` 로 변경, 목록 조회에서 제외 |

### FR-12 · 신청 수락

| 항목 | 내용 |
| --- | --- |
| 사용자 | 모집자 |
| 선행 조건 | 대기 상태의 신청 |
| 담당 | 4 |

**처리 절차**

```
  1. 신청을 조회한다
  2. 모집자 본인인지 확인한다
  3. 상태가 대기인지 확인한다
  4. 현재 수락 인원과 정원을 비교한다

  6. 마지막 자리를 채웠으면 모집글을 마감한다

**정원이 차면 모집글도 마감한다.** 별도 처리를 두지 않고 수락 시점에 함께 판단한다.

| --- | --- | --- |

| 이미 처리됨 | 400 | `ALREADY_PROCESSED` |
| 모집자가 아님 | 403 | `FORBIDDEN` |
| 대상 부재 | 404 | `NOT_FOUND` |

### FR-15 · 후기 등록

| 항목 | 내용 |
| --- | --- |
| 사용자 | 참여자 |
| 선행 조건 | 마감된 모집글, 모집자이거나 수락된 신청 보유 |
| 담당 | 5 |

**입력 항목**

| 항목 | 필수 | 제약 |
| --- | --- | --- |
| 내용 | 예 | 500자 이하 |
| 평점 | 예 | 1 이상 5 이하 |

**처리 절차**

```
  1. 모집글을 조회한다
  2. 상태가 마감인지 확인한다
  3. 모집자이거나 수락된 신청이 있는지 확인한다
  4. 이미 작성했는지 확인한다
  5. 저장한다
```

**모집자도 참여자이다.** 모집자는 신청 절차를 거치지 않으므로 수락된 신청이 존재하지 않는다. 요구사항 정의서의 참여자 정의가 이를 포함한다.

**예외 처리**

| 상황 | 응답 | 코드 |
| --- | --- | --- |
| 검증 실패 | 400 | `INVALID_INPUT` |
| 마감되지 않음 | 400 | `STUDY_NOT_CLOSED` |
| 이미 작성함 | 400 | `DUPLICATE_REVIEW` |
| 참여자가 아님 | 403 | `FORBIDDEN` |
| 대상 부재 | 404 | `NOT_FOUND` |

**팀 판단 · BR-14**

| 선택 | 절차 4 |
| --- | --- |
| 채택 | 작성 이력을 확인하고 `DUPLICATE_REVIEW` 반환 |
| 미채택 | 절차 4를 두지 않으며 해당 코드를 쓰지 않는다 |

### FR-16 · 후기 삭제

| 항목 | 내용 |
| --- | --- |
| 사용자 | 작성자 |
| 선행 조건 | 자기 후기 |
| 담당 | 5 |

**처리 절차**

```
  1. 후기를 조회한다
  2. 작성자 본인인지 확인한다
  3. 삭제한다
```

**모집자에게 삭제 권한을 주지 않는다.** 낮은 평점을 지울 수 있게 되어 후기의 의미가 사라진다.

**예외 처리**

| 상황 | 응답 | 코드 |
| --- | --- | --- |
| 인증 부재 | 401 | `UNAUTHORIZED` |
| 작성자가 아님 | 403 | `FORBIDDEN` |
| 대상 부재 | 404 | `NOT_FOUND` |

### FR-17 · 내 정보 조회

| 항목 | 내용 |
| --- | --- |
| 사용자 | 회원 |
| 선행 조건 | 로그인 |
| 담당 | 6 |

**처리 절차**

```
  1. 토큰에서 회원 식별자를 확인한다
  2. 회원을 조회한다
  3. 이메일, 별명, 가입일을 반환한다
```

**비밀번호를 반환하지 않는다.** 변환된 값이라도 응답에 담지 않는다.

**예외 처리**

| 상황 | 응답 | 코드 |
| --- | --- | --- |
| 인증 부재 | 401 | `UNAUTHORIZED` |

## 04. 상태 전이

### 모집글

```
  RECRUITING ──▶ CLOSED
```

| 전이 | 조건 | 주체 |
| --- | --- | --- |
| 모집 중 → 마감 | 모집자가 마감 | 모집자 |
| 모집 중 → 마감 | 마지막 자리가 수락으로 채워짐 | 시스템 |

**마감일이 지나도 상태는 그대로 둔다.** 자동 전환 처리를 두지 않으며 신청 시점에 날짜를 함께 확인한다.

### 신청

```
  PENDING ──▶ ACCEPTED
          ├─▶ REJECTED
          └─▶ (삭제)
```

| 전이 | 조건 | 주체 |
| --- | --- | --- |
| 대기 → 수락 | 정원 여유 있음 | 모집자 |
| 대기 → 거절 | 없음 | 모집자 |
| 대기 → 삭제 | 없음 | 신청자 |

**수락과 거절은 되돌릴 수 없다.** 한 번 처리된 신청은 다시 바꾸지 않으며 취소도 되지 않는다.

**팀 판단 · BR-15 미채택 시**

```
  PENDING ──▶ CANCELED
```

상태 값이 하나 늘 뿐이며 표 구조는 바뀌지 않는다.

## 06. 판단 위치

| 판단 | 위치 | 근거 |
| --- | --- | --- |
| 값의 형식과 범위 | 요청 형태 | 저장소에 가기 전에 걸러진다 |
| 소유 관계 | 업무 계층 | 대상을 조회해야 알 수 있다 |
| 상태 전이 | 업무 계층 | 현재 상태를 조회해야 알 수 있다 |

**요청 형태에서 걸러지는 것과 업무 계층에서 걸러지는 것을 나눈다.** 정원이 1 이상인지는 값만 보면 알 수 있으나, 수락 인원보다 작은지는 자료를 조회해야 알 수 있다.
